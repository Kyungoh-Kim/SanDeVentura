## 1. 요약

SanDeVentura MVP는 공식 등산로 데이터가 부족하거나 신뢰하기 어려운 작은 산과 비공식 길에서 하이커가 잘못된 갈림길로 들어서는 위험을 줄이는 제품이다.

제품은 산행 기록을 오프라인으로 저장하고, 산행이 끝난 뒤 연결이 가능할 때 완료 세션을 업로드하며, 반복 GPS 흔적을 검증해 신뢰도 표시가 있는 대표 경로로 변환한다. MVP의 핵심 질문은 다음과 같다.

> "나는 사람들이 주로 이용하는 경로 근처에 있는가, 아니면 우연한 샛길로 벗어나고 있는가?"

MVP는 완전한 공식 지도나 등산 커뮤니티를 만들지 않는다. 목표는 경로 정보가 약한 곳에서 갈림길 판단의 불확실성을 줄이는 것이다.

## 2. 목표

공식 경로 데이터가 부족한 환경에서도 사용자가 오프라인으로 산행을 기록하고, 누적된 흔적을 바탕으로 조심스럽게 해석 가능한 참고 경로를 받을 수 있음을 검증한다.

핵심 결과:

| 항목 | 목표 |
|------|------|
| KR1 | 베타 사용자가 비행기 모드에서 30분 산행을 기록하고 앱 재시작 후에도 세션을 복구할 수 있다 |
| KR2 | 완료된 세션은 연결 복구 후 중복 기여 없이 업로드된다 |
| KR3 | 최소 세 개 베타 산을 경로 없음, 참고 경로, 추천 경로 중 하나로 분류할 수 있다 |
| KR4 | 대표 경로가 있는 산에서 현재 위치와 경로 사이의 최근접 지점, 거리, 경로 상태를 반환한다 |
| KR5 | 데이터 근거가 약한 경로는 추천 경로가 아니라 참고 경로로 표시한다 |

## 3. 대상 사용자

### 주요 사용자: 동네 산을 걷는 일반 하이커

- 작은 산이나 중간 규모 산을 걷는다.
- 불명확한 갈림길이나 비공식 길을 만난다.
- 공식 코스 이름이나 등산로 ID를 모를 수 있다.
- 전문 GIS 정보보다 단순한 신뢰도 기반 안내가 필요하다.

### 보조 사용자: 반복 방문 하이커

- 같은 산을 여러 번 방문한다.
- 반복 기록을 통해 같은 산의 경로 품질을 높인다.
- 누적된 경로가 점점 더 신뢰 가능해지는 과정을 체감한다.

### 운영자: 1인 제품/개발 담당자

- 기록, 업로드, 경로 추론이 정상 작동하는지 확인해야 한다.
- 데이터 부족, GPS 노이즈, 갈림길 모호성, 알고리즘 임계값 문제를 구분할 수 있어야 한다.

## 4. MVP 사용자 흐름

1. 사용자가 산행 지역을 선택하거나 확인한다.
2. 사용자가 산행을 시작한다.
3. 앱은 네트워크가 없어도 위치 포인트를 로컬에 저장한다.
4. 앱이 재시작되면 활성 세션을 복구한다.
5. 사용자가 산행을 종료한다.
6. 첫 업로드 전 위치 업로드 동의 안내를 확인한다.
7. 온라인 상태가 되면 완료 세션을 한 번만 업로드한다.
8. 시스템은 잘못된 포인트를 필터링하고 승인된 경로 증거를 저장한다.
9. 시스템은 대표 경로 후보를 생성하거나 갱신한다.
10. 사용자는 경로 없음, 참고 경로, 추천 경로 중 하나의 상태를 본다.
11. 갈림길에서 현재 위치와 대표 경로를 비교해 거리와 경로 상태를 확인한다.

## 5. P0 기능

| 번호 | 기능 | 요구사항 | 수용 기준 |
|------|------|----------|-----------|
| P0-1 | 오프라인 기록 | 네트워크 없이 산행을 기록할 수 있다 | 비행기 모드 30분 기록이 로컬에 유지된다 |
| P0-2 | 세션 복구 | 활성 세션은 앱 재시작 후에도 유지된다 | 재시작 후 같은 세션이 복구되고 중복 세션이 생기지 않는다 |
| P0-3 | 멱등 업로드 | 완료 세션은 재시도되어도 한 번만 기여한다 | 반복 업로드가 하나의 기여로 처리된다 |
| P0-4 | 포인트 검증 | 잘못된 포인트는 거절되거나 낮은 품질로 처리된다 | 업로드 결과에 승인/거절 포인트 수가 포함된다 |
| P0-5 | 무기반 경로 추론 | 공식 경로 없이도 반복 흔적으로 참고 경로를 만들 수 있다 | 산 상태가 경로 없음에서 참고 경로로 전환될 수 있다 |
| P0-6 | 신뢰도 표시 | 사용자는 경로 신뢰도를 볼 수 있다 | confidence >= 0.70은 추천, 그 미만은 참고 또는 미추천으로 표시된다 |
| P0-7 | 현재 위치 비교 | 현재 위치와 대표 경로를 비교할 수 있다 | 최근접 경로 지점, 거리, 경로 상태를 반환한다 |
| P0-8 | 업로드 동의와 프라이버시 | 위치 흔적은 동의 후 업로드되고 다른 사용자에게 원시 경로로 노출되지 않는다 | 업로드 요청은 동의 버전을 포함하고, 하이커 API는 대표 경로와 스냅 결과만 노출한다 |

## 6. P1 / P2

P1:

- 기본 운영 지표.
- 경로 품질 디버그 신호.
- 비슷한 지지를 받는 갈림길을 보수적으로 처리.

P2:

- 공식 등산로 데이터 연계.
- 오프라인 지도 타일.
- 리뷰, 사진, 커뮤니티.

## 7. 기술 방향

현 MVP 구현 권장 스택:

- Android-first Flutter 앱.
- 로컬 SQLite: 오프라인 세션, 활성 세션 복구, 업로드 큐, 트랙 포인트.
- Supabase Auth: MVP 사용자 인증.
- Supabase Postgres + PostGIS: 공간 데이터 저장, 거리 계산, 대표 경로.
- Supabase Edge Functions: 멱등 업로드, 포인트 검증, 대표 경로 조회, 위치 스냅.

## 8. 무기반 경로 추론

MVP는 완벽한 자동 지도 제작이 아니라, 설명 가능한 참고 경로 생성을 목표로 한다.

1. 좌표 유효성, 정확도, Haversine 속도, 고도 점프, 고립 포인트 필터로 원시 포인트를 정리한다.
2. 승인된 포인트를 약 8m-15m 크기의 H3 또는 fixed-size cell로 집계한다.
3. cell별 포인트 수, 고유 세션 수, 평균 정확도, 최근성, 고도, 진입/이탈 방향을 추적한다.
4. 지지가 낮거나 고립된 cell을 제거한다.
5. 시간순 cell sequence에서 session transition graph를 만든다.
6. 약한 edge를 제거하고 largest connected component를 선택한다.
7. weighted shortest path 또는 highest-support path로 가장 강한 경로를 추출한다.
8. cell center를 LineString으로 변환한다.
9. 비슷한 지지를 받는 갈림길이 있으면 confidence를 낮춘다.

## 9. 프라이버시와 보존 기준

- 완료 세션은 민감한 위치 흔적을 포함하므로 첫 sync 전에 업로드 동의가 필요하다.
- 사용자는 sync하지 않음으로써 완료 세션을 로컬에만 유지할 수 있다.
- 다른 사용자의 원시 경로, 원시 포인트, 신원은 하이커용 API에 노출하지 않는다.
- 원격 승인 포인트는 베타 경로 학습에 사용하며, 거절 포인트는 전체 원시 payload보다 구조화된 요약을 우선 저장한다.
- MVP 이벤트 payload에는 전체 좌표 배열을 저장하지 않는다.
- 상세 기준은 `privacy-retention.md`를 따른다.

## 10. 초기 경로 판정 기준

초기 beta 기본값:

- `<= 25m`: on route.
- `> 25m and <= 50m`: caution.
- `> 50m`: away from route.

이 값은 필드 테스트 후 조정할 수 있다.
